# Portfolio Content Guide

This document keeps portfolio copy concise, consistent, and recruiter-friendly.

## Content order

Each major section should answer questions in this order:

1. What is this?
2. Why does it matter?
3. What did I build or contribute?
4. Which technologies were used?
5. What can a visitor do next?

## Project case studies

For every featured project, keep the same structure:

- One-sentence summary
- Problem or goal
- Key features
- Technical decisions
- Current status
- Links to repository or live product when available

## Writing rules

- Prefer short paragraphs and concrete language.
- Avoid repeating the same skill list in multiple sections.
- Lead with outcomes and responsibilities, then implementation details.
- Keep experimental work clearly labelled.
- Do not claim production scale, users, or metrics unless verified.

## Maintenance

Review portfolio copy whenever a featured project changes substantially. Remove outdated technology names, broken links, stale availability text, and old project status labels.
